Validation or verification?

An online form asks for a person's age. One person types 250. Another means to type 52, but types 25. Each mistake needs a different kind of check.

Validation
Verification
250 is not a possible age. A rule rejects it.
25 is a possible age, so no rule can reject it. A person must check it.
Done automatically by the program.
Checks the data entered is the data that was meant.
Checks data is reasonable.
Checks data has not changed when it was entered.

Validation cannot tell you that data is correct. 25 passes a range check from 0 to 120, even though the person is 52.

Key words

validation
An automatic check that data is reasonable.
verification
A check that data has not changed when it was entered.
test data
Values chosen to test that a program works.
extreme
The largest or smallest acceptable value.
boundary
The largest or smallest acceptable value, and the first rejected value past it.

Six validation checks

Each check tests one thing about the data. Learn the name, what it checks, and one example.

Range

The value is between two limits
Mark 0 to 100

Length

The number of characters
Password 8 or more

Type

The data type
Age is an INTEGER

Presence

Some data has been entered
Name not empty

Format

The pattern of the data
dd/mm/yyyyhas an @

Check digit

Detects errors in entered or transmitted data
last digit of a bar code

A check digit is worked out from the other digits, often with MOD. If one digit is typed wrongly, the check digit no longer matches.

3

A validation loop

An IF checks the input once, so a second wrong input is accepted. A loop checks after every input, until the input is valid.

WHILE: the condition is the invalid case

OUTPUT "Enter a mark from 0 to 100"
INPUT Mark
WHILE Mark < 0 OR Mark > 100 DO
    OUTPUT "The mark must be from 0 to 100"
    INPUT Mark
ENDWHILE

REPEAT: the condition is the valid case

REPEAT
    OUTPUT "Enter a mark from 0 to 100"
    INPUT Mark
UNTIL Mark >= 0 AND Mark <= 100

The same loop in Python

mark = int(input("Enter a mark from 0 to 100: "))
while mark < 0 or mark > 100:
    mark = int(input("The mark must be from 0 to 100: "))

OR becomes AND

WHILE keeps going while the mark is wrong: below 0 OR above 100.

UNTIL stops when the mark is right: 0 or more AND 100 or less.

Four things to include

  • a loop: WHILE or REPEAT
  • the input, and the input again inside the loop
  • the correct condition
  • a prompt and an error message

6

Common mistakes

✗ An IF to validate

An IF asks again only once. A second wrong value gets through.

✓ A WHILE or REPEAT loop that asks again until the value is valid

✗ AND in the WHILE condition

WHILE Mark < 0 AND Mark > 100 is never TRUE: no mark is both.

✓ WHILE Mark < 0 OR Mark > 100

✗ No INPUT inside the loop

The value never changes, so the loop never stops.

✓ The error message, then INPUT again, inside the loop

✗ Extreme data that is rejected

Extreme values are inside the range. 101 is not extreme for 0 to 100.

✓ Extreme: 0 or 100. Boundary rejected: -1 or 101

✗ Mixing up validation and verification

A double entry check is verification, not validation.

✓ Validation: range, length, type, presence, format, check digit. Verification: visual, double entry

✗ > and >= mixed up

Age > 11 rejects 11 when 11 is allowed.

✓ Read "inclusive" as >= and <=

In the exam

Write a validation algorithm

Marks go to the loop, the input, the condition and the messages. Write all four, even when the question is short.

Choose test data

Give a value and say what it tests. For a range of 1 to 50: normal 25, abnormal 60, extreme 1 or 50, boundary 0 or 51.

Name the check

Match the check to what the rule tests: a number of characters is length; an '@' or a date pattern is format; something entered is presence.
