Inheritance and polymorphism

A child class takes everything its parent has, then changes the one thing that differs. Two lines of Python do it, and the second question of a Paper 4 class scenario usually asks for them.

1

One class built on another

A bike character in a game is a character. It has a name and a position like every other character, and it moves in the same four directions. The only difference is that it travels further in one step. Writing a second class from nothing would repeat everything the first already says.

Inheritance says that the new class is a kind of the old one. The child gets every attribute and every method of the parent without them being written again, and then changes or adds only what differs.

Key words

inheritance
One class taking the attributes and methods of another.
parent, superclass
The class being inherited from.
child, subclass
The class doing the inheriting.
override
To replace an inherited method with a different one of the same name.
polymorphism
The same method name behaving differently depending on the class of the object.
containment
One object holding another as an attribute. The syllabus also calls this aggregation.
2

The two lines that do it

Inheritance in Python is the parent's name in brackets after the child's name, and a call to the parent's constructor from inside the child's.

class BikeCharacter(Character):
    def __init__(self, NameP, XPositionP, YPositionP):
        super().__init__(NameP, XPositionP, YPositionP)

The brackets name the parent. super() means the parent class, so super().__init__(...) runs the parent's constructor and lets it set the attributes it already knows how to set. The child's constructor does not repeat those assignments.

That is the whole of it. The object that comes out has every method of the parent:

Karla = BikeCharacter("Karla", 50, 50)
print(Karla.GetXPosition(), Karla.GetYPosition())
50 50

GetXPosition is written once, in the parent, and works on an object of the child class without appearing in it.

When the child has attributes of its own

A child that adds an attribute calls the parent constructor for the shared ones and then assigns its own.

class Cat(Pet):
    def __init__(self, GivenName, GivenBreed):
        super().__init__(GivenName)
        self.Breed = GivenBreed

Count the parameters

The child constructor takes every parameter the object needs, including the ones it passes straight on. A question that gives the parent five attributes and the child two will ask for a child constructor with seven parameters.

3

Overriding

A method written in the child with the same name as one in the parent replaces it for objects of the child class. Nothing marks it as a replacement. The name alone does that.

    def Move(self, Direction):
        if Direction == "up":
            super().SetYPosition(20)
        elif Direction == "down":
            super().SetYPosition(-20)
        elif Direction == "right":
            super().SetXPosition(20)
        elif Direction == "left":
            super().SetXPosition(-20)

The parent's Move moves 10. This one moves 20 and is otherwise identical. It still calls the parent's set methods, so the limits written once in the parent still apply.

Extending rather than replacing

An overriding method can call the parent's version and add to it, rather than ignoring it. This is useful where the child does everything the parent does and a little more. Here Pet already has a Description method, and the child keeps what that returns and adds to the end of it.

class Duck(Pet):
    def Description(self):
        return super().Description() + " and it swims"

Which one runs

Python looks in the object's own class first. If the method is there, that one runs. If it is not, Python looks in the parent.

So a child with no Move uses the parent's, and a child with one uses its own, with no change to the code that calls it.

4

Polymorphism

Two objects of different classes are sent the same instruction and each does the right thing for its own class. The code that sends the instruction does not need to know which class it is dealing with.

Jack = Character("Jack", 50, 50)
Karla = BikeCharacter("Karla", 50, 50)

for Who in (Jack, Karla):
    Who.Move("up")
    Who.Move("right")

print(Jack.GetXPosition(), Jack.GetYPosition())
print(Karla.GetXPosition(), Karla.GetYPosition())
60 60
70 70

Both start in the same place and both receive the same two instructions. The loop contains no test of what kind of character it is holding. Python chooses the method from the class of the object, and that choice is what polymorphism means.

This matters in a Paper 4 answer because it removes a block of IF statements. A question that asks for every object in an array to be output can be answered with one loop calling one method name, where each class has its own version of that method.

Prove it

Start both objects at the same position, send both the same calls, and print both results. Identical starting values and identical instructions are what make the different answers evidence of anything.

Containment

Containment is one object holding another as an attribute. The syllabus also calls it aggregation. It is not inheritance, and the test for which one a design needs is a short question.

RelationshipThe testExampleIn Python
InheritanceIS-AA bike character is a character.class BikeCharacter(Character):
ContainmentHAS-AA game has a player.self.__Player = Character(...)
class Game:
    #self.__Title string
    #self.__Player Character

    def __init__(self, TitleP, PlayerP):
        self.__Title = TitleP
        self.__Player = PlayerP

    def GetPlayerName(self):
        return self.__Player.Name
ThisGame = Game("Race", Karla)
print(ThisGame.GetPlayerName())
Karla

The Game object reaches the character it holds and asks it for something. An attribute of a class can be an object of another class, and the comment block names that class as the data type.

Choosing between them

Say the sentence out loud. "A bike character is a character" is true, so inheritance. "A game is a character" is false and "a game has a character" is true, so containment.

Common mistakes

✗ The parent is not named

class BikeCharacter: declares a class that inherits nothing, and every parent method is then missing.

✓ class BikeCharacter(Character):

November 2023 Paper 41 Question 3(c)(i), where the header is one of three marks.

✗ The attributes are written again

The child repeats the parent's assignments instead of calling the parent constructor, so the inheritance does no work.

✓ super().__init__(NameP, XPositionP, YPositionP)

The same question. The call to the parent constructor is a mark of its own.

✗ Not every parameter is passed on

The child constructor takes three and passes two to the parent, so one attribute is never set.

✓ Pass every parameter the parent needs, in the order it expects them.

June 2025 Paper 42 Question 3(b)(i), where the constructor takes six.

✗ The overriding method is given a new name

BikeMove() does not override anything. The parent's Move is still what runs when Move is called.

✓ Use the same name as the parent's method.

November 2023 Paper 41 Question 3(c)(ii).

✗ The override changes nothing

A method that is copied from the parent without the change the question asks for earns the header mark and no more.

✓ Make the stated change, then test it against an object of the parent class.

The same question, where the second mark is for the values changing by 20.

✗ Limits re-written in the child

Copying the validation into the child means two copies to keep in step, and the question did not ask for it.

✓ Call the parent's set method and let the limits stay in one place.

June 2023 Paper 41 Question 2(b)(ii), which limits to a maximum height.

✗ Inheritance where containment is meant

A class that holds another is not a kind of it. A game is not a character.

✓ Apply the IS-A and HAS-A test before writing either.

Any question whose design shows one class as an attribute of another.

✗ A test that proves nothing

Two objects started at different positions will give different answers whether the override works or not.

✓ Start both at the same values and send both the same calls.

Any part that asks for a screenshot of the output.

8

In the exam

Inheritance is examined often and in a predictable shape. The question builds a parent class in its first part and asks for a child in a later one.

Declare the child class

November 2023 Paper 41 Question 3(c)(i) gives three marks: the header naming the parent, the constructor taking all three parameters, and the call to the parent constructor with those parameters. June 2025 Paper 42 Question 3(b)(i) gives four for the same shape with a six parameter constructor.

Then override a method

November 2023 Paper 41 Question 3(c)(ii) gives two marks: the method header overriding the parent's, and the change the question describes. June 2025 Paper 42 Question 3(b)(ii) gives two for an overriding method that builds on the parent's result rather than replacing it.

A child with attributes of its own

June 2023 Paper 41 Question 2(b)(i) gives five marks for a class inheriting from a parent with three further private attributes of its own, their data types, and a constructor taking at least five parameters.

Polymorphism in the main program

June 2023 Paper 41 Question 2(c) gives three marks for output across objects of more than one class, where the marks go to one method per class and to the main program choosing correctly between them.

Evidence

Program code is copied into the numbered part of the evidence document, and where a part asks for a test, a screenshot of the output goes beside it. An override is only visible in output, so a part that asks for a screenshot is asking for proof that the child behaves differently from the parent.

Check your own child class

  • Is the parent named in the brackets?
  • Does the constructor call the parent constructor?
  • Does every parameter reach the parent, in order?
  • Does the overriding method have the same name as the parent's?
  • Have you run one object of each class, from the same starting values?
