Reading and writing text files

Every Paper 4 since 2021 has supplied a text file. The same few lines of Python open it, read every line into an array, and write an array back out again.

1

Opening a file

A file has to be opened before anything can be read from it or written to it, and closed when the work is finished. The mode given when it is opened decides what is allowed and what happens to whatever the file already holds.

File = open("TheData.txt", "r")
File.close()

Three modes are examined. The difference between the last two is the one that costs marks: opening a file for writing empties it, and opening it for appending does not.

ModePythonWhat it does
Readopen(Name, "r")Opens an existing file so its lines can be read. Fails if the file is not there.
Writeopen(Name, "w")Creates the file if it does not exist, and empties it if it does. Everything that was in it is lost.
Appendopen(Name, "a")Creates the file if it does not exist, and adds to the end of it if it does. Nothing is lost.

Key words

text file
A file of lines of text, read and written one line at a time.
mode
Read, write or append. Given when the file is opened.
EOF
End of file. The point where there are no more lines to read.
line break
The invisible character at the end of each line, written in Python as \n.
record
One line of the file, holding the values for one thing.
2

Reading every line

A line read from a file arrives with its line break still attached. The character does not show in printed output, and removing it is a mark point in several mark schemes.

File = open("TheData.txt", "r")
Line = File.readline()
File.close()
print(Line)
print(repr(Line))
print(repr(Line.strip()))
10,red

'10,red\n'
'10,red'

The blank line in the output is the line break being printed. repr() shows what the string actually holds, and strip() removes the break and any spaces at either end. The mark schemes award a mark for removing the line break, so strip() goes on every line as it is read.

The standard shape

This is the function that Paper 4 asks for most often: open the file, read every line into an array, close the file, return the array.

def ReadData():
    DataArray = []
    File = open("TheData.txt", "r")
    for Line in File:
        DataArray.append(Line.strip())
    File.close()
    return DataArray

Data = ReadData()
print(len(Data), Data[0])
72 10,red

for Line in File reads to the end of the file whatever its length, which is what a question means when it says the function must work for a file with an unknown number of lines. A loop counting to a fixed number does not.

Where the question asks for the filename to be entered rather than written into the program, one more line does it, and the name read from the user is passed to open().

FileName = input("Enter the filename")
File = open(FileName, "r")

Opening and closing

The mark schemes pair them in a single mark point: opening the file in the right mode and closing it in an appropriate place.

Closing it after the loop, not inside it, is what an appropriate place means.

3

Splitting a line

A line often holds more than one value, separated by a comma. split() cuts the line at every comma and returns the pieces as an array of strings.

Line = "10,red"
Parts = Line.split(",")
Number = int(Parts[0])
Colour = Parts[1]
print(Number + 5, Colour)
15 red

Everything that comes out of a file is a string, including a line that looks like a number. int() converts it, and without that conversion arithmetic and numerical comparisons do the wrong thing or stop the program. The same applies to float() where the file holds decimals.

Where the split is done on a line that has not been stripped, the last piece carries the line break, so strip() comes first.

Prove the conversion

Print Parts[0] + 5 without the int() and read the error. Then print Parts[0] + "5" and read the answer.

One stops the program and one gives 105. Neither is the sum.

4

Writing and appending

Writing is the same four steps in the other direction: open in the right mode, loop through the data, write each item, close the file.

Red = [10, 28, 46]

File = open("Red.txt", "w")
for Item in Red:
    File.write(str(Item))
    File.write("\n")
File.close()

Two things here are marks of their own. write() takes a string and nothing else, so a number has to go through str() first. And write() adds no line break, so without the second write() the whole array lands on one line. The file now holds:

10
28
46

Appending to a file that already has data

Changing the mode to "a" changes nothing else. Each run adds to the end rather than starting again.

File = open("Red.txt", "a")
File.write("64\n")
File.close()
10
28
46
64

Building a line from several values

Where each line of the new file holds several values separated by commas, the line is built as a string first and written in a single call.

Line = str(Node[0]) + "," + str(Node[1]) + "," + str(Node[2])
File.write(Line + "\n")

Which mode the question wants

Read the verb. Stores the content in a new file means write. Adds each item to the file means append.

November 2025 Paper 42 Question 3(d) asks for a new file. June 2025 Paper 41 Question 2(c) asks for each item to be appended to a new line.

5

When the file is not there

Opening a file that does not exist stops the program. Because the file is outside the program's control, every file operation is wrapped so that a missing or unreadable file produces a message instead of a crash.

def ReadData():
    DataArray = []
    FileName = input("Enter the filename")
    try:
        File = open(FileName, "r")
        for Line in File:
            DataArray.append(Line.strip())
        File.close()
    except:
        print("Cannot open file")
    return DataArray

The mark point is worded as exception handling with an appropriate output, so all three parts are needed: the try, the except, and a message that says what went wrong. A try with an empty except earns nothing.

This is a mark point in nineteen of the twenty-nine mark schemes from June 2021 to November 2025, and thirteen of those question papers put it in the wording of the question. Exception handling has its own guide; what matters here is that it belongs around every file operation whether the question asks for it or not.

Worth a mark on its own

In June 2025 Paper 41 Question 2(a) the question says nothing about exception handling, and the mark scheme still lists it among the points available.

Pseudocode and Python

A question describes the file operations in pseudocode. These are the parts that change on the way into Python.

Cambridge pseudocode
Python
OPENFILE "Data.txt" FOR READ
File = open("Data.txt", "r")
The mode is part of the command in pseudocode and the second argument in Python.
OPENFILE "Data.txt" FOR WRITE
File = open("Data.txt", "w")
Both empty the file. Any data already in it is lost.
OPENFILE "Data.txt" FOR APPEND
File = open("Data.txt", "a")
Both add to the end of whatever is already there.
READFILE "Data.txt", LineOfText
LineOfText = File.readline()
Reads the next line into a string variable.
WHILE NOT EOF("Data.txt")
for Line in File:
Both run to the end of the file. The Python loop reads the line as well, so there is no separate read inside it.
WRITEFILE "Data.txt", LineOfText
File.write(LineOfText + "\n")
The pseudocode command writes a whole line. Python writes exactly the string given, so the line break is added.
CLOSEFILE "Data.txt"
File.close()
Pseudocode names the file, Python uses the variable returned by open().

Common mistakes

✗ The line break is left on

A line read from the file is "red\n", so comparing it with "red" is false and the data goes into the wrong place.

✓ DataArray.append(Line.strip())

Removing the line break is its own mark point in several mark schemes, June 2024 Paper 42 Question 1(a) among them.

✗ The file is opened for writing when the question says add

Mode "w" empties the file as it is opened, so the data that was to be added to is no longer there.

✓ Use "a" where the question says append or add to the file.

June 2025 Paper 41 Question 2(c), where the procedure appends each item to a new line.

✗ The file is never closed

The program may still run, but the mark pairs opening the file with closing it, so the mark is lost.

✓ File.close() after the loop, before the function returns.

Phrased in the mark schemes as closing the file in an appropriate place.

✗ The file is opened inside the loop

Opening on every pass starts reading from the first line again, or, in write mode, empties the file on every pass.

✓ Open once, loop, close once.

Any question that reads or writes a whole file.

✗ A fixed count where the length is unknown

for i in range(50) stops early on a longer file and fails on a shorter one.

✓ for Line in File runs to the end whatever the length.

June 2025 Paper 41 Question 2(a), which states the file has an unknown number of lines.

✗ Everything is written on one line

write() adds no line break, so the whole array becomes a single line of the file.

✓ Write "\n" after each item, or write Item + "\n".

A mark of its own in June 2025 Paper 41 Question 2(c).

✗ A number is written straight to the file

File.write(10) stops the program, because write() takes a string and nothing else.

✓ File.write(str(Item))

Any part that writes numbers out of an array.

✗ The values are used as strings

Data read from a file is text, so "9" is treated as larger than "10" and sums give the wrong answer.

✓ int(Parts[0]) as the value comes out of the line.

June 2025 Paper 41 Question 2(b), where the integer is separated from the colour.

In the exam

Every one of the twenty-nine Paper 4 papers from June 2021 to November 2025 supplies or requires a text file.

Read a file into an array

November 2024 Paper 41 Question 1(a) gives six marks for a function that declares an array, opens Data.txt to read, loops through the file storing each line, closes the file, returns the array, and handles the exception. June 2025 Paper 41 Question 2(a) gives seven for the same shape with the filename entered by the user and an unknown number of lines.

Read a file straight into a structure

November 2025 Paper 42 Question 3(c) gives four marks for a main program that reads each integer from the file and calls the procedure that adds a node to a binary tree. June 2023 Paper 41 Question 3(b)(iii) does the same with a stack, for five.

Write an array out to a file

June 2025 Paper 41 Question 2(c) gives five marks for a procedure that takes an array and a filename, opens the file to append, writes each item on its own line, closes the file and handles the exception. November 2025 Paper 42 Question 3(d) gives five for writing each node as a comma separated line to a file the candidate has to create.

Evidence

Program code is copied into the numbered part of the evidence document. Where a part asks for a screenshot of a file that the program has written, the filename has to be visible in the screenshot as well as the contents.

Check your own file code

  • Is the mode the one the question asks for?
  • Is the file closed, after the loop?
  • Is the line break stripped as each line is read?
  • Is each value converted before it is used as a number?
  • Is a line break written after each item?
  • Is the whole thing inside try and except, with a message?
